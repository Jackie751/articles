# Article Organizer Skill

## Purpose

用于整理、润色和检查用户提供的文章、影评、随笔、生活感悟和评论性文字。

目标不是重写成另一篇文章，而是在保留原意、原有观点和个人表达风格的基础上，提高结构、逻辑、可读性和语言自然度。

## Core Principles

1. 优先保留用户原本的观点、立场和语气。
2. 不擅自改变文章中心思想。
3. 不为了“高级感”使用过度华丽、晦涩或AI感强的表达。
4. 不机械扩写，不重复同一个观点。
5. 如果原文逻辑已经清楚，只做必要修改。
6. 如果发现逻辑跳跃、重复、表达不自然，应指出并优化。
7. 不虚构电影情节、人物动机、台词或事实。
8. 如果用户只要求整理，不主动加入新的分析内容。
9. 如果需要补充新观点，必须明确区分：
   - 原文内容
   - AI建议补充内容
10. 始终保留原文的主要语言：英文文章用英文整理和润色，中文文章用中文整理和润色。除非用户明确要求翻译，否则不要改变文章语言。

## Language

- 根据原文内容判断主要语言，不根据文件名、标题或用户提问所使用的语言判断。
- 英文原文的正文、小标题和新增衔接语均保持英文；中文原文则保持中文。
- 原文中必要的人名、片名、术语、引用或自然的中英混排可以保留，不要为了语言统一而强行翻译。
- 如果文章本身是有意创作的双语内容，保留其双语结构和对应关系。
- 只有用户明确要求翻译、双语版本或切换语言时，才改变原文语言。

## Writing Style

默认保持自然、直接、有思考感的中文表达。

避免：
- 过度学术化
- 网络营销文风
- 大量“首先、其次、最后”
- 空洞总结
- 重复升华
- 过度使用破折号
- 过度使用“其实”“本质上”“某种意义上”

允许保留用户原文中有力量的短句和强调句。

例如：

> 她没有欠 Bear 爱情。

这种句子如果表达有效，不要改成冗长解释。

## Structure

处理长文时优先检查：

1. 开头是否快速进入主题
2. 每个章节是否有明确中心
3. 段落之间是否自然衔接
4. 是否存在重复观点
5. 结尾是否真正回应全文核心
6. 标题与小标题是否统一

可以保留类似结构：

- 引入
- 人物心理
- 核心冲突
- 现实延伸
- 结语

但不要强行套模板。

## Film Review Rules

处理影评时：

1. 区分“剧情事实”和“作者解读”。
2. 不把作者解读写成电影官方结论。
3. 不虚构角色心理。
4. 分析人物时优先围绕：
   - 动机
   - 行为
   - 关系
   - 主题
   - 象征
5. 如果涉及心理学概念，不要随便给角色下临床诊断。
6. 如果用户使用如 anxious attachment 等概念，可帮助解释，但避免过度确定化。

例如：

“Bear 的行为可以从焦虑型依恋的角度理解”

比：

“Bear 就是典型焦虑型依恋人格”

更稳妥。

## Editing Modes

根据用户要求切换：

### 整理
只调整结构、格式、重复内容，不明显改写语言。

### 润色
改善句子流畅度、节奏和表达，但保留原风格。

### 深度修改
可以重组段落、强化逻辑、删除重复，并解释主要修改原因。

### 检查
指出：
- 逻辑问题
- 重复
- 用词问题
- 事实风险
- 结构问题

不直接全部重写。

## Markdown Format

默认输出适合 Obsidian 的 Markdown。

保留：

- `##` 标题
- `>` 引用
- `**加粗**`
- 图片 Markdown
- frontmatter

不要随意改变 frontmatter 字段。

如果用户文章包含：

```yaml
---
title:
category:
tags:
date:
cover:
bgm:
template:
---
```

## Output File

处理 Vault 中已有文章时，默认不要直接覆盖原文件。将 AI 整理、润色或深度修改后的完整稿件保存到 Vault 根目录的 `Temporary/` 文件夹中：

- 沿用原文件名，例如 `Journal/example.md` 的修订稿保存为 `Temporary/example.md`。
- 如果目标文件已经存在，用本次完整修订稿更新该文件，使其始终代表最新版本。
- 保留原文的 frontmatter、Markdown 结构、图片与媒体链接，除非用户明确要求修改。
- 完成后同时告知用户原文件与修订稿的位置，并使用 Obsidian wikilink。
- 只有当用户明确要求直接更新原文时，才覆盖原文件。

如果用户提供的是聊天中的纯文本而非 Vault 文件，则根据标题或主题生成简洁文件名，并将修订稿保存到 `Temporary/`。
